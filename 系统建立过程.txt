================================================================================
一、项目起源与原型阶段
================================================================================

项目最初的目标是构建一个基于 RAG（检索增强生成）技术的临床辅助决策系统，
帮助医护人员进行诊断辅助、知识检索和用药安全核查。

技术选型决策：
  - 大模型：选择阿里云 DashScope 通义千问（qwen3-max），因其在中文医疗
    场景表现良好，且国内访问稳定
  - 嵌入模型：DashScope text-embedding-v4，用于文本向量化
  - 向量数据库：ChromaDB，轻量级、易于嵌入 Python 应用
  - RAG 框架：LangChain，提供完整的 RAG 组件链
  - 原型框架：Streamlit，快速验证核心功能

原型阶段的核心文件均位于 RagProject/ 目录下。


================================================================================
二、Streamlit 原型实现（RagProject/）
================================================================================

──────────────────────────────────────────────────────────────────────────────
2.1 核心 RAG 引擎搭建
──────────────────────────────────────────────────────────────────────────────

第一步是实现 RAG 的核心能力：文档检索 + 大模型生成。

关键文件：rag.py、vector_stores.py、knowledge_base.py、config_data.py

实现步骤：
  1. 配置 DashScope API（config_data.py）
     - 从环境变量 DASHSCOPE_API_KEY 读取 API Key
     - 配置 embedding 模型和 LLM 模型参数

  2. 实现向量存储服务（vector_stores.py）
     - 封装 ChromaDB 的初始化和检索操作
     - 提供 get_retriever() 方法返回 LangChain 检索器

  3. 实现知识库管理（knowledge_base.py）
     - 支持 PDF、DOCX、TXT 三种文件格式的文本提取
     - 使用 RecursiveCharacterTextSplitter 进行文本分块
     - 将文本块向量化后存入 ChromaDB
     - 使用 MD5 校验避免重复上传

  4. 构建 RAG 处理链（rag.py）
     - 使用 LangChain Expression Language (LCEL) 构建链
     - 链结构：检索 → 格式化文档 → 构建提示词 → 调用 LLM → 输出
     - 支持流式输出（stream）

  5. 实现聊天历史存储（file_history_store.py）
     - 继承 LangChain 的 BaseChatMessageHistory
     - 将会话历史存储为 JSON 文件
     - 支持多会话管理

──────────────────────────────────────────────────────────────────────────────
2.2 知识库数据准备
──────────────────────────────────────────────────────────────────────────────

为了支撑临床辅助决策，准备了以下知识库文档：
  - clinical_diagnostic_criteria.txt：临床诊断标准
  - disease_symptom_mapping.txt：疾病-症状映射关系
  - drug_safety.txt：药物安全信息
  - drug_safety_structured.txt：结构化药物安全数据
  - medication_recommendations.txt：用药推荐
  - recommended_exams.txt：推荐检查项目

这些文档通过知识库上传功能导入 ChromaDB，形成 RAG 的检索基础。

──────────────────────────────────────────────────────────────────────────────
2.3 Streamlit 多页面应用
──────────────────────────────────────────────────────────────────────────────

关键文件：app_qa.py（单文件多页面应用）

使用 Streamlit 构建了包含以下功能的单页面应用：
  - 侧边栏导航：首页、知识库管理、智能问答、鉴别诊断、用药安全、
    诊断记录管理、操作日志
  - 首页仪表盘：显示文档统计、诊断统计等数据
  - 知识库管理：上传/查看/删除文档
  - 智能问答：多轮对话界面
  - 鉴别诊断：输入症状生成鉴别诊断建议
  - 用药安全核查：输入药物信息进行安全评估
  - 诊断记录管理：增删改查
  - 操作日志：查看系统操作记录

Streamlit 阶段使用 JSON 文件存储数据（users.json、diagnosis_records.json、
operation_log.json、chat_history/*.json）。

五、数据库迁移（JSON → SQLite）
================================================================================

初始原型使用 JSON 文件存储数据，随着功能增加，JSON 文件方式暴露出
查询效率低、并发访问不安全等问题，因此迁移到 SQLite。

──────────────────────────────────────────────────────────────────────────────
5.1 迁移策略
──────────────────────────────────────────────────────────────────────────────

在 rag/database.py 中实现数据迁移函数：
  - migrate_users_from_json()：从 users.json 迁移用户数据
  - migrate_diagnosis_from_json()：从 diagnosis_records.json 迁移诊断记录
  - migrate_logs_from_json()：从 operation_log.json 迁移操作日志
  - migrate_chat_history_from_json()：从 chat_history/*.json 迁移对话历史
  - run_all_migrations()：执行所有迁移

迁移逻辑：
  - 检查 .db_migrated 标记文件，避免重复迁移
  - 逐条读取 JSON 数据并插入 SQLite 表
  - 迁移完成后创建标记文件

──────────────────────────────────────────────────────────────────────────────
5.2 双数据库访问模式
──────────────────────────────────────────────────────────────────────────────

迁移后存在两套数据库访问代码：
  1. backend/app/core/database.py：FastAPI 服务层使用的数据库模块
  2. backend/app/rag/database.py：RagProject 原始模块使用的数据库模块

两者连接同一个 app_data.db 文件，保持数据一致性。

项目发展到一定阶段后，原始结构存在以下问题：

──────────────────────────────────────────────────────────────────────────────

  - 统一路径配置，所有路径基于 backend/ 目录
  - 保持前后端完全分离

步骤 1：创建 backend/app/rag/ 包

    config_data.py、database.py、user_auth.py、diagnosis_records.py、
    operation_log.py、dashboard_data.py、knowledge_base.py、
    vector_stores.py、rag.py、file_history_store.py、report_generator.py

步骤 3：更新 import 语句

  - from database import xxx → from .database import xxx
  - 涉及 8 个文件：database.py、vector_stores.py、knowledge_base.py、
    rag.py、file_history_store.py、dashboard_data.py、
    diagnosis_records.py、operation_log.py

步骤 4：更新 services/ 模块
  - 移除所有 sys.path hack 代码（约 15 行/文件）

七、关键技术实现细节
================================================================================

──────────────────────────────────────────────────────────────────────────────
7.1 RAG 链构建（rag_service.py）
──────────────────────────────────────────────────────────────────────────────

RAG 处理链使用 LangChain 的 LCEL 语法构建：

  1. 用户输入 → 检索器（ChromaDB 相似度搜索）
  2. 检索结果 → format_document() 格式化
  3. 格式化后的文档 + 对话历史 → 构建提示词
  4. 提示词 → ChatTongyi（通义千问）→ 生成回复

提示词模板包含：
  - 系统角色设定（临床辅助决策助手）
  - 检索到的相关知识
  - 对话历史上下文
  - 用户当前问题

──────────────────────────────────────────────────────────────────────────────
7.2 单例模式实现
──────────────────────────────────────────────────────────────────────────────

RagService 和 KnowledgeBaseService 使用单例模式：

  _instance = None

  def __new__(cls):
      if cls._instance is None:
          cls._instance = super().__new__(cls)
          cls._instance._initialized = False
      return cls._instance

  def __init__(self):
      if self._initialized:
          return
      # 初始化逻辑（只执行一次）
      self._initialized = True

这样确保全局共享同一个 ChromaDB 连接和 LLM 实例，避免重复初始化。

──────────────────────────────────────────────────────────────────────────────
7.3 文件上传与文本提取
──────────────────────────────────────────────────────────────────────────────

支持三种文件格式：
  - PDF：使用 PyMuPDF（fitz）提取文本
  - DOCX：使用 python-docx 提取文本
  - TXT：直接读取文本内容

上传流程：
  1. 接收上传文件
  2. 计算文件 MD5，检查是否已存在
  3. 提取文本内容
  4. 使用 RecursiveCharacterTextSplitter 分块（chunk_size=500, chunk_overlap=50）
  5. 生成向量嵌入
  6. 存入 ChromaDB
  7. 记录 MD5 到 md5.txt

──────────────────────────────────────────────────────────────────────────────
7.4 诊断报告 PDF 生成
──────────────────────────────────────────────────────────────────────────────

使用 ReportLab 库生成专业格式的 PDF 诊断报告：
  - 包含医院标题、患者信息、诊断结果、治疗建议等
  - 使用自定义样式（标题字体、表格样式、段落格式）
  - 支持中文显示

──────────────────────────────────────────────────────────────────────────────
7.5 前端 ECharts 图表
──────────────────────────────────────────────────────────────────────────────

Dashboard.vue 使用 ECharts 展示三种图表：
  - 诊断趋势折线图：显示近 7 天每日诊断数量变化
  - 疾病分布饼图：显示各疾病诊断占比
  - 知识库文件分布饼图：显示各来源文档数量占比

图表在数据加载完成后通过 nextTick() 确保 DOM 渲染完毕后再初始化。

──────────────────────────────────────────────────────────────────────────────
7.6 操作日志系统
──────────────────────────────────────────────────────────────────────────────

所有关键操作都会记录日志，包括：
  - 登录/注册
  - 诊断记录的增删改
  - 知识库文档的上传/删除
  - AI 问答
  - 鉴别诊断
  - 用药安全核查

日志记录包含操作时间、操作类型、操作详情、操作人和操作状态。

──────────────────────────────────────────────────────────────────────────────
7.7 诊断记录同步到知识库
──────────────────────────────────────────────────────────────────────────────

特色功能：将诊断记录格式化为知识库文本，上传到 ChromaDB。
这样后续类似的病例查询时，RAG 可以检索到历史诊断记录作为参考。

格式化模板包含：患者信息、症状、检查、诊断结果、治疗方案。
